# 云端搭建步骤（微信云开发）

> 结论先放前面：**不用买服务器、不用备案域名、不用写后端接口**。
> 这个项目的云端 = 微信云开发（Serverless），共 **4 个云函数 + 4 个集合**。
> 全程在开发者工具里点，约 30 分钟。

---

## 0. 先理解：哪些功能用云，哪些不用

| 功能 | 存哪 | 说明 |
|---|---|---|
| 喝水/饮食/睡眠/训练打卡 | **手机本地** | `wx.setStorageSync`，不联网也能用 |
| 积分与等级 | 本地 + 云端 | 本地先记，联网后通过 `dt_score` 补推，幂等 |
| 昵称 / 头像 / 隐身 | 云端 `dt_users` | 榜单要给别人看 |
| 搭子关系 | 云端 `dt_buddies` | 双向各存一行 |
| 邀请码 | 云端 `dt_invites` | 6 位码，7 天有效，一次性 |
| 排行榜 | 云端 `dt_scores` + 聚合 | 只算「我 + 我的搭子」，不是全服榜 |

**关键设计**：小程序端 `miniprogram/utils/` 里没有任何一处 `wx.cloud.database()`，
所有数据库读写都在云函数里（管理端权限）。所以数据库权限可以放心设成最严的那档。

## 1. 开通云开发（5~10 分钟）

### 1.1 三个前置条件（缺一个按钮就点不动）

| 条件 | 怎么确认 |
|---|---|
| 项目用的是**正式 AppID** | 工具右上角「详情 → 基本信息 → AppID」应是 `wxcd93e2f7ac0846a9`；若是 `touristappid` 说明是游客模式，云开发、上传都不能用 |
| 登录的是**管理员或开发者**微信 | 工具左下角头像 → 若不是你自己，退出重扫 |
| 开发者工具是**较新版本** | 菜单「帮助 → 检查更新」；工具栏没有「云开发」按钮，八成是版本太旧 |

> 不需要买服务器、不需要域名备案、不需要单独写后端接口。

### 1.2 创建环境

1. 打开微信开发者工具并打开本项目，点顶部工具栏 **「云开发」**（图标在「上传」左边一带）
2. 首次点会弹出开通页 → 勾选同意协议 → **开通**
3. 点 **「新建环境」**：
   - 环境名称：`dalilun`（只是给自己看，随便起）
   - 计费方式：选 **免费云环境**（新账号赠送资源点，约 40,000 点/月，可体验 6 个月，不支持按量付费）
   - 确认后等 **1~3 分钟**初始化，状态变成「可用」才算建好
4. **抄下环境 ID**：形如 `dalilun-3gxxxxxx`。
   位置：云开发控制台左上角环境名旁边，或「设置 → 环境设置」里的「环境 ID」。
   ⚠️ 抄的是 **ID**（带随机后缀），不是「环境名称」。

> 已有环境的话，进控制台左上角确认选中的是哪个环境，直接读它的 ID，跳过创建。

### 1.3 两个入口别混淆

| 入口 | 在哪 | 用来干什么 |
|---|---|---|
| 开发者工具内 | 顶部「云开发」按钮 | 建环境、看数据库、部署云函数、看日志 |
| 网页控制台 `cloud.weixin.qq.com` | 浏览器，管理员微信扫码 | 出门在外改数据、看用量账单、配告警 |

两边看到的是**同一套数据**，只是界面不同。控制台左上角的环境下拉框决定你看的是哪个环境，切错环境会以为"数据丢了"。

## 2. 把环境 ID 填进代码（1 分钟，最容易漏）

打开 `miniprogram/config.js` 第 8 行左右：

```js
module.exports = {
  version: '1.1.1',
  cloudEnvId: '',        // ← 把这里改成 'dalilun-3gxxxxxx'
  ...
}
```

改成：

```js
  cloudEnvId: 'dalilun-3gxxxxxx',
```

**不填的后果（很隐蔽）**：`app.js` 里是 `if (config.cloudEnvId && wx.cloud)` 才初始化，
不填的话整个应用**静默走本地降级** —— 不报错、不白屏，只是排行榜显示「本地单机」。
很多人以为云没生效，其实只是这一行没填。

改完点「编译」重新跑一次。

> **本项目当前状态（2026-10-21）**：已填入 `cloud1-d3ghwmm9qac18a1e7`（v1.1.2）。
> 剩下的是：建 4 个集合 + 建索引 + 部署 4 个云函数 + 重新上传代码。

---

## 3. 建 4 个集合（5 分钟）

云开发控制台 → **数据库** → 「+」新建集合，逐个创建，名字必须一模一样（区分大小写）：

| 集合名 | 存什么 | 权限设置 |
|---|---|---|
| `dt_scores` | 每条打卡得分（一行一个模块一天） | **仅管理端可读写** |
| `dt_users` | 昵称、头像 key、隐身开关 | **仅管理端可读写** |
| `dt_buddies` | 搭子关系，双向各一行 | **仅管理端可读写** |
| `dt_invites` | 6 位邀请码、过期时间、使用者 | **仅管理端可读写** |

权限在哪改：集合右侧 **「权限设置」** → 选「仅管理端可读写」。

为什么敢全部锁死？因为客户端一次都没直连数据库，全部经云函数；
云函数用的是管理端身份，不受这条权限限制。**这是最安全也最省心的配置。**

---

## 4. 建索引（5 分钟，不建会算错分）

云开发控制台 → 数据库 → 点进集合 → **索引管理** → 添加索引。

| 集合 | 索引字段（顺序不能反） | 唯一 | 为什么需要 |
|---|---|---|---|
| `dt_scores` | `_openid` ↑, `date` ↑, `module` ↑ | ✅ 是 | 云函数靠它做幂等：同一天同一模块只能加一次分 |
| `dt_scores` | `date` ↑ | ❌ 否 | 周榜/日榜要按日期范围筛 |
| `dt_users` | `_openid` ↑ | ✅ 是 | 一人一条档案，防止 upsert 出重复 |
| `dt_buddies` | `_openid` ↑, `buddyOpenid` ↑ | ✅ 是 | 防止重复添加同一个搭子 |
| `dt_invites` | `code` ↑ | ❌ 否 | 核销时按码查；量大再改唯一 |

**漏建第一条的后果**：`dt_score` 云函数里那个 `isDup()` 的兜底就失效了，
同一模块反复点能给同一人重复加分，榜单分数虚高。这是本项目云端唯一的强依赖。

---

## 5. 部署 4 个云函数（10 分钟）

开发者工具左侧文件树 → 展开 `cloudfunctions/` → 逐个右键：

```
cloudfunctions/
├── dt_buddy     ← 邀请码 / 搭子关系
├── dt_profile   ← 昵称头像 upsert   （函数名与集合名不同，别改）
├── dt_rank      ← 榜单聚合
└── dt_score     ← 发分（幂等 + 服务器时间）
```

每个都右键 → **「上传并部署：云端安装依赖（不上传 node_modules）」**

- 不要选「上传并部署：所有文件」，会把本地 node_modules 一起传，又慢又容易失败
- 依赖已在各自 `package.json` 里声明（`wx-server-sdk ~2.6.3`），云端会自动装
- 部署成功的标志：底部控制台出现 `上传成功`；云开发控制台 → 云函数 能看到 4 个函数

> 云函数代码用的是 `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`，
> 会自动跟随「调用方所在的环境」，所以以后开测试环境也不用改代码。

**部署耗时**：每个函数首次 20~60 秒（云端要装 `wx-server-sdk`），4 个加起来约 2~3 分钟。
排队时不要重复点，重复点会弹「正在部署中」。

**⚠️ 本项目特别提醒**：`dt_score` 里除了 `submit`，还有 `revoke` 分支（当天记录改成不达标时删掉云端那条分）。
必须部署当前这版代码，否则撤销会返回 `BAD_ACTION`，榜单上留着一笔已经不该存在的分。
以后每次改云函数，都要重新「上传并部署」一次——云函数不会跟着小程序代码一起上传。

## 6. 验证（3 步，5 分钟）

1. **发分链路**：模拟器里随便完成一项打卡（比如喝够水）→ 云开发控制台 → 数据库 → `dt_scores`
   应该多出一条记录，`_openid` 是你自己的，`points` 为 10
2. **榜单链路**：进「榜单」页 → 不再显示「本地单机」，能看到自己一行、分数不为 0
3. **日志**：云开发控制台 → 云函数 → 点 `dt_score` → 调用日志，最近一次应是 `ok: true`

三条都过 = 云端通了。真机再扫一次码确认一遍更稳。

## 7. 十个常见坑（按踩到的概率排序）

| # | 现象 | 原因 | 怎么修 |
|---|---|---|---|
| 1 | 榜单一直显示「本地单机」，但没报错 | `config.js` 的 `cloudEnvId` 没填 | 填上，重新编译 |
| 2 | 报 `collection not exists`（-502005） | 集合没建或名字拼错 | 对照第 3 节，注意大小写 |
| 3 | 报 `cloud function not found`（-501000） | 云函数没部署，或部署到了别的环境 | 重部署，确认环境和环境 ID 一致 |
| 4 | 分数能重复加 | 唯一索引没建 | 补 `dt_scores` 的三字段唯一索引 |
| 5 | 云函数返回「没有身份信息」 | 开发者工具未登录，或扫码的是游客 | 用管理员/开发者微信登录后重进 |
| 6 | 改了 `config.js` 还是不生效 | 没重新编译，或缓存了旧包 | 工具菜单「清缓存 → 全部清除」再编译 |
| 7 | 云函数调用超时 | 首次冷启动 + 云端装依赖慢 | 等 10 秒重试，第二次就快 |
| 8 | 换了环境后数据全空 | 云开发环境之间数据不互通 | 确认控制台左上角选的是同一个环境 |
| 9 | 数据库有记录但榜单查不到 | `dt_buddies` 没数据（榜单只算自己和搭子） | 这是设计如此，不是 bug |
| 10 | 提示欠费/额度用尽 | 免费额度耗尽 | 控制台「设置 → 计费」看用量，个人项目几乎撞不到 |

## 8. 成本与容量（给你一个量级感）

云开发现在是**资源点**计费，1,000 点 = 1 元：

| 套餐 | 额度 | 价格 |
|---|---|---|
| 免费云环境（新账号首次） | 约 40,000 资源点/月 | 0 元，单次续期 6 个月，**不支持按量付费**，超量直接不可用 |
| 基础 / PERSONAL | 约 40,000 资源点/月 + 支持按量 | 19.9 元/月（原价 39，长期 5 折） |

本项目用量：

- 一个用户一天：4 次写（打卡）+ 5 次读（榜单/服务器时间）≈ 每月 300 次调用
- 100 个用户 ≈ 每月 3 万次调用、存储 1 万条记录约 1MB —— **免费额度完全盖得住**
- 云函数每次运行按 256MB × 运行时长计，冷启动 1 秒内，单次不到 0.3 点

**真正的风险不是钱，是配额被刷**：免费环境超量会直接不可用（不会扣费），付费环境超量按量扣钱。
上线后到网页控制台「设置 → 告警」配一个费用阈值（比如 10 元），比事后看账单强。

> 不想花钱怎么办：不开云开发也能用，只是排行榜显示「本地单机」、搭子/邀请码不可用。
> 打卡数据和积分全部在本机，不影响主流程。

## 9. 上线前还要做的一件事

云端通了之后，**回到开发者工具重新「上传」一次代码**（因为 `config.js` 改了）。
否则线上跑的版本里 `cloudEnvId` 还是空的，用户装到的就是纯单机版。

顺序永远是：改 `config.js` → 部署云函数 → 验证 → 上传代码 → 提交审核。
